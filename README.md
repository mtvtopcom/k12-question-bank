## 项目定位

本项目从零开始构建，目标是工程化地生产大规模、高质量、结构化的 K12 选择题。核心理念是**源头治理**：先把知识点按权威课标梳理干净、结构化，再用代码管道批量出题——而不是逐题手工堆砌。

整个系统由两层构成：

1. **知识点地图（`knowledge-map/`）**：覆盖幼儿园 / 小学 / 初中 × 语文 / 数学 / 英语，共 63 册，每条知识点带课标领域、学习目标、难度、认知层级、前置关系、易错点、权威来源等 15 个字段。这是全项目唯一的知识点数据源。
2. **生成管道（`src/` + `scripts/`）**：读取知识点地图，用双引擎出题，经质量门禁校验后入库，导出为多种格式。

## 这个项目能做什么

一句话：**把「课标知识点」变成「可直接粘贴给大模型的出题指令」，或直接在桌面端填自己的 API Key 出题入库；并附带一套能管、能改、能校验的知识点地图。**

| 你是 | 可以怎么用 |
|---|---|
| 中小学老师 / 教研员 | 按册次查知识点 → 勾选多个点 → 生成提示词粘贴到 DeepSeek / 元宝 / ChatGPT，或在「大模型API生成」页填自己的 Key 直接出题入库，一次 1—100 道带答案与解析 |
| 家长 | 按年级定位薄弱知识点，生成同步练习，不用买教辅 |
| 开发者 / 创业者 | 直接消费 63 册结构化知识点（JSON / JSONL / CSV），接入自己的组卷、测评、错题本产品 |
| 研究者 / 课程设计者 | 课标领域、认知层级、难度、前置关系齐全，可做知识图谱、学习路径与难度校准研究 |

## 核心设计

| 特性 | 说明 |
|---|---|
| **知识点地图先行** | 63 册 / 1225 个知识点（幼儿园 9 + 小学 36 + 初中 18）已全部完成，依据国家课标独立梳理 |
| **双引擎 + 母题变体** | 规则类科目（数学/英语/语文基础）走模板引擎，成本≈0；语义类走 LLM 生成母题，程序化扩展 1→8，把 API 调用压到 1/8 |
| **确定性 ID** | `id = sha256(topic_id + variant + seed)`，重跑幂等，断点续传不重复扣费 |
| **质量门禁** | 结构校验 → 答案一致性 → 语义去重（字符 n-gram Jaccard）→ 难度校准 → 抽检 |
| **配置驱动** | 年级、科目、配额、难度分布、模型、并发、导出格式全在 `config/config.yaml` |
| **可插拔** | 知识点源、生成引擎、LLM provider、导出器均为独立模块 |

## 快速开始

```bash
# 1. 查看进度、领取下一册梳理任务
python3 knowledge-map/tools/progress.py --next 5

# 2. 生成某册的梳理提示词，交给 AI 梳理并写入 volumes/
python3 knowledge-map/tools/progress.py --prompt primary-g2-s1-math

# 3. 校验 → 合并 → 生成题目（端到端）
python3 knowledge-map/tools/validate.py
python3 knowledge-map/tools/merge.py
python3 scripts/run_from_map.py --try-run          # 试跑：仅模板引擎，无需 API key
python3 scripts/run_from_map.py --per-topic 24 --subject math   # 按科目生成

# 4. 全量生成（语义类题目需配 LLM key）
export DEEPSEEK_API_KEY=sk-xxxx
python3 scripts/run_full.py --target 100000 --resume

# 5. 题库质量验证
python3 scripts/verify.py
```

> **注意**：LLM key 从环境变量读取，绝不落盘。provider 按 OpenAI 兼容格式编写，换 Qwen / 豆包只改 `base_url` 与 `model`。

## 知识点体系

依据 2022 版义务教育课程标准（已联网核准）：

- **数学**：数与代数 / 图形与几何 / 统计与概率 / 综合与实践
- **语文**：六大学习任务群（语言文字积累与梳理 / 实用性阅读与交流 / 文学阅读与创意表达 / 思辨性阅读与表达 / 整本书阅读 / 跨学科学习）
- **英语**：六要素（主题 / 语篇 / 语言知识 / 文化知识 / 语言技能 / 学习策略）× 三主题范畴
- **学段**：S1(1-2年级) / S2(3-4) / S3(5-6) / S4(7-9)
- **幼儿园**：《3-6岁儿童学习与发展指南》五大领域（健康 / 语言 / 社会 / 科学 / 艺术）

单条知识点含 15 个字段，详见 [SCHEMA.md](knowledge-map/SCHEMA.md)。逐册梳理工作流见 [knowledge-map/README.md](knowledge-map/README.md)。

## 题目 Schema

统一结构，所有导出格式（JSONL / App JSON / CSV）都从它派生：

```json
{
  "id": "a1b2c3...",
  "topic_id": "primary-g6-s1-math-K016",
  "grade": "六年级上", "subject": "math", "topic": "圆的周长",
  "difficulty": 2, "bloom": "理解", "type": "single_choice",
  "stem": "某部分占整体的30%，对应扇形圆心角是多少度？",
  "options": ["30°", "108°", "90°", "72°"],
  "answer": "B",
  "explanation": "圆心角 = 360° × 30% = 108°",
  "source": "template|llm", "generator_version": "v1.0",
  "quality": {"dedup_hash": "...", "qa_passed": true}
}
```

## 生成题目的输出格式（对接文档）

桌面端「AI 提示词」支持 4 种输出格式，大模型按对应指令返回。完整字段说明、示例、解析代码与校验规则见 **[docs/OUTPUT_FORMATS.md](docs/OUTPUT_FORMATS.md)**，并附 [JSON Schema](docs/question-output.schema.json) 与 [4 种格式示例文件](docs/samples/)。

| 格式 | 结构 | 关键点 | 适用场景 |
|---|---|---|---|
| **JSON** | 顶层数组，每题一个对象 | `options` 为 4 元数组；`answer` 为 A–D；`difficulty` 为 1–4 | 程序直接入库 |
| **TXT** | 逐题分段，题间空行 | `【题干】【选项】【答案】【解析】【难度】【知识点】` | 人工阅读、贴进 Word |
| **Excel** | TSV（制表符），12 列 | 复制到 Excel A1 → 另存 `.xlsx` | 老师批量校对 |
| **CSV** | RFC 4180，12 列，同表头 | UTF-8 BOM；含逗号/引号/换行时加引号 | 导入表格 / 数据库 |

公共字段：`topic_id`、`topic_name`、`stem`、`options`（表格格式为 `option_a`…`option_d`）、`answer`、`explanation`、`difficulty`、`bloom`、`type`。

Excel / CSV 的 12 列顺序固定：`topic_id, topic_name, stem, option_a, option_b, option_c, option_d, answer, explanation, difficulty, bloom, type`。

```json
[{"topic_id":"primary-g3-s1-math-K018","topic_name":"长方形、正方形的特征与周长","stem":"一个长方形花坛长 8 米、宽 5 米，绕它走一圈是多少米？","options":["26 米","13 米","40 米","21 米"],"answer":"A","explanation":"绕一圈即周长，(8+5)×2=26 米。","difficulty":2,"bloom":"应用","type":"single_choice"}]
```

> 仓库管道自身导出的 JSONL / CSV / App JSON（`src/exporters.py`）字段不同，如何映射成 `id / grade / subject / topic` 见文档第 8 节。

### 内容感知型模板生成器（v1.2，已实现）

旧模板引擎用硬编码词表出题（成语只有 4 个、拼音只有 5 个），理论上限约 995 道不重复题。
v1.2 的 `src/generators/content_aware.py` 改为**读取每个知识点自身内容**命题：

- 把 `explanation` 拆成 concept（具体做法/事实）与 mistakes（`易错点：` 之后的典型误区）
- **v1.2.1 重大调整：移除「领域归类 / 目标匹配 / 前置知识」等元数据题型**——那些题把知识点名当题干、考它的档案字段，不是考学习内容
- 题干围绕 `objective`（考核要求）设置情境，选项全部是**内容陈述**：
  - 要点判断：concept 的具体做法为正确项，典型误区 + 同学科同领域要点为干扰项
  - 误区识别：典型误区为答案，正确做法为干扰项
  - 术语填空：把 concept 含「关键术语」的原句挖空，术语为答案（干扰项取同学科术语）
- 每类配 6 套句子结构不同的问法模板，穿越 quality 的字符 n-gram 去重门禁
- 数学运算类知识点额外走参数化数值题（按年级限制运算种类，幼儿园严格去小学化不出算式）
- 原本路由到 LLM 的语义类知识点，在无 API key 时也能用它出有意义的题

实测容量（v1.2.1 内容题策略）：单点数学约 10 题、语文约 9 题、英语约 8 题；
全库估算约 **1.1 万道不重复题**，仍是旧引擎（约 995 题）的 10 倍以上。
v1.2.1 移除元数据题型后容量比 v1.2.0（约 1.3 万）略降，这是主动的质量取舍——宁可少出，不出把知识点当档案考的题。
为保证质量，初中数学的抽象符号运算、幼儿园的算式训练都主动放弃数值题——同样宁缺毋滥。默认已启用（`config.yaml: template.content_aware: true`），
设 `false` 可回退旧引擎做对比。配套把去重门禁改为按 n-gram 数量分桶比对（判定结果与原全表比对 0 差异），
避免全库数万题时的 O(n²) 卡顿。可用 `python3 scripts/verify_content_aware.py` 一键验证生成器正确性。

> 距 10 万题仍需 LLM 引擎补量：内容感知的问法模板终究有限，语义类题目（阅读、作文、
> 古诗赏析）需要 LLM 保证质量。

### 大模型出题提示词（当前主推路径）

模板引擎的固有局限是题干结构有限、情境单薄。桌面 app v1.2.0 起改为**提示词驱动**：
在「AI 提示词」模块勾选知识点后生成一份可直接粘贴到 DeepSeek / 元宝 / ChatGPT 的指令
（`desktop/src/prompt.py`），包含：

- 完整知识点档案（学段、年级、考核要求、核心概念、易错点、难度、认知层级、前置、来源）
- 命题规则，**明确禁止「知识点归入哪个领域」这类档案题**，要求情境化题干与同质干扰项
- **年级红线**：明确要求「题目禁止超出当前选择年级的水平」，按各知识点所属学段年级给出具体禁区（如幼儿园禁算式、低年级禁多步运算、初中禁高中内容）
- **难度分布**：按四级占比用最大余数法换算成各难度题数，提示词写明每级各出几题
- **题目来源**：每题必须带 `topic_id` / `topic_name`，标明来源于哪个知识点，便于入库溯源
- 严格 JSON 输出 Schema（来源 / 题干 / 选项 / 答案 / 解析 / 难度 / 认知层级）
- 按学科匹配的 few-shot 示例

支持单选、多选、全选；每知识点题数可选 1/3/5/10/15/20/50/100 或自定义任意正整数，难度以「容易 / 中等 / 较难 / 难」四档显示，
可用预设（基础为主 / 均衡 / 进阶 / 挑战）或自定义四级百分比，实时显示换算后的各档题数。
筛选栏学段 / 科目 / 年级默认「全部」且学段与年级联动。可在线微调文本、一键复制、导出 `.txt` / `.md`。
本地模板引擎保留在「工具 → 本地模板引擎（旧）」仅供对比。

## macOS 桌面管理台

不写网页，做成双击即开的原生 macOS 桌面窗口（Python 标准库 + 系统 Tcl/Tk，零第三方依赖、无需 Xcode）。

**方式一：直接下载**（推荐给非开发者）——到 [Releases](https://github.com/mtvtopcom/k12-question-bank/releases/latest) 下载 `K12-Question-Bank-v1.8.1-macos.zip`，解压后双击 `K12 题库工厂.app`。首次打开若提示「未验证的开发者」，右键 → 打开即可。

**方式二：从源码构建**

```bash
python3 desktop/build_app.py      # 生成 desktop/K12 题库工厂.app（只需一次）
open "desktop/K12 题库工厂.app"   # 或直接双击
```

> 桌面端需要带 tkinter 的 Python 3：推荐 python.org 官方安装包，或 `brew install python-tk`。系统自带的 `/usr/bin/python3` 可能不含 tkinter。

功能：

v1.8.0 起接口配置只露 5 个必填项，其余参数收进「高级设置」，每项都有 ? 讲白话；v1.7.0 起 API 页的生成内容用大号高亮摘要、任务名收短到「年级 学科 · 知识点」、日志可清空并恢复「打开生成文件夹」；v1.6.0 起每个生成任务都有自己的名字和独立 JSON 存档，任务与进度明细都能删改；v1.5.0 起「生成什么」与「怎么生成」分开：模块二只负责勾选与参数，模块三只负责模型配置与进度。界面分为四个标签页，互不干扰（v1.3.1 统一品牌为「K12 题库工厂」并换用项目 Logo 图标；v1.3.2 优化知识点勾选与排序交互；v1.3.3 勾选框尺寸调协调并固定浅色界面；v1.3.4 支持四种大模型输出格式；v1.3.5 知识点管理页改版并支持一键恢复出厂配置）：

**模块一 · 知识点管理**

- **浏览**：左侧知识地图按 学段 → 科目 → 年级 → 册 组织，默认全部收起，逐层点开；中间表格列出知识点（含学科、年级列），下方以「字段名: 值」单行紧凑展示 12 个字段
- **筛选**：关键词全文搜索 + 难度（容易/中等/较难/难）/ 认知层级过滤，默认「全部」，点列头排序
- **管理**：新增 / 编辑 / 删除知识点，改动直接写入 `knowledge-map/volumes/`（下游出题实际消费的数据）
- **恢复原始配置**：一键把整库还原为软件安装时的 63 册 / 1225 个知识点（`desktop/original/` 出厂快照）；恢复前自动整库备份，误操作可用「撤销」回到恢复前状态
- **安全**：每次写操作自动备份到 `desktop/backups/`、记入 `desktop/changelog.jsonl`，「撤销」可恢复
- **校验 / 导出**：一键跑三套校验；当前结果导出 CSV / JSON

**模块二 · 选择知识点生成内容（主推）**

- **筛选**：学段 / 科目 / 年级三个下拉默认「全部」；选学段后年级联动收窄（选小学只列 1—6 年级，不再显示 7/8/9 年级）。所有下拉单击展开、单击选项即选中
- **列表**：含学科、认知层级列，难度以「容易 / 中等 / 较难 / 难」文字显示；勾选框与行高比例协调，点任意行即可勾选（整行变蓝），Shift + 点击可连选区间，点「选」表头按已选/未选排序；另有「全选当前」「清空选择」「反选」
- **参数**：每知识点题数可选 1/3/5/10/15/20/50/100 或「自定义」任意正整数；难度预设默认「基础为主」（50/30/15/5），也可选均衡/进阶/挑战或自定义四级百分比，实时显示按题数换算的各档题数；「输出格式」可选 JSON（便于入库）/ TXT（便于阅读）/ Excel（制表符表格，复制到 Excel 另存 .xlsx）/ CSV（可直接导入表格）
- **生成**：勾 1 个出单点提示词，勾多个出批量提示词；含完整档案、年级红线、难度分布、来源字段，以及所选输出格式的字段说明与示例
- **使用**：文本框可微调，「复制全部」粘贴到 DeepSeek / 元宝 / ChatGPT，或导出 `.txt` / `.md`；点「本地API生成」带着当前勾选与题数直接跳到模块三
- **本地模板出题（旧）**：收在「工具 → 本地模板引擎」，用固定模板现场出题，仅作效果对比

**模块三 · 大模型 API 生成**

- **三种协议**：OpenAI 兼容（DeepSeek / 通义千问 / Kimi / 智谱 / 豆包 / OpenAI / Ollama）、Anthropic Claude、Google Gemini。选预设自动填 Base URL 与模型，只需粘贴自己的 API Key
- **配置安全**：保存在用户数据目录（macOS `~/Library/Application Support/K12题库工厂/config.json`），文件权限 600；「测试连接」验证地址 / Key / 模型是否可用，Key 不写入日志与导出文件
- **本页只配模型**：知识点勾选、每点题数、难度配比全部沿用模块二，页面顶部显示「已选 N 个知识点 · 每点 M 题 · 预计多少题」与各档实际分配，点「去选择知识点」可回去改
- **进度与断点**：进度条 + 知识点明细 + 运行日志 + token 用量，等待模型响应时显示「已等待 N 秒」；限流与超时的每次重试都写进日志（第几次、多久后重试）；「暂停」「停止」立即生效（在途请求直接放弃，半秒内停下），暂停时明细与任务状态显示「已暂停」，已生成题目都保留；关掉软件后重开会把上次残留的「生成中」自动校正为「已暂停」，点「继续」从断点续跑
- **生成内容摘要**：页面顶部用大号彩色横条写明「已选 N 个知识点 · 每点 N 题」，并以红色标出「预计 N 题」，下面一行是难度配比与每档实际题数，一眼看清这一跑会生成什么
- **任务管理**：任务名按「年级 学科 · 知识点」自动生成（多个知识点显示「首个 等 N 点」），点「重命名」可改成好记的名字；进度明细里「删除选中」移除知识点行（按住 Command 多选）、「清空明细」移除全部，都只调整本任务要生成什么，不动已入库题目；「删除任务」删掉任务进度与它的 JSON 存档，题库里的题目保留；「打开生成文件夹」一键打开 `exports/`
- **运行日志**：等待/重试/入库逐条记录，可随时「清空日志」（只清屏，不影响进度与题库）
- **小白友好**：接口区只留协议、预设、模型、Base URL、API Key 五个必填项；灵活度、输出上限、等待上限、请求间隔、每次题数、固定格式（JSON）都收进「高级设置」，收起时用一句话显示当前值。每项旁边有蓝色 ?：鼠标停留给一句白话，点一下弹出完整说明（是什么、怎么调、不调会怎样），默认值都能直接用。参数超出范围会直接提示可填区间，不会悄悄改成别的值
- **按任务存档**：每个任务在数据目录 `exports/` 下实时写一份独立 JSON（文件名 = 任务名），每入库一批就更新；配合题库页的「按任务导出 JSON」可把筛选结果按任务拆成多个文件，文件名同样是任务名
- **质量兜底**：自动剥离 ```json 围栏与多余解释，校验 4 个选项、答案唯一、解析非空、难度合法；重复题干按 `topic_id + 题干` 哈希去重，不会重复入库或重复计费；网络错误与 5xx 自动退避重试，401/403/404 立即中止并说明原因
- **直存入库**：生成结果写入本地题库，可在「题库」页继续筛选、预览与导出

**模块四 · 题库**

- **浏览**：最新在前，按关键词 / 学科 / 年级 / 难度筛选；选中即看完整题干、选项、答案、解析、来源模型、所属任务与生成时间
- **导出**：当前筛选结果导出 JSON / JSONL / CSV / Excel `.xlsx` / TSV，默认文件名 `K12题库_日期`，可直接给表格工具或其他程序调用；「按任务导出 JSON」选一个文件夹，每个任务写一份「任务名.json」
- **安全**：删除所选、清空题库前自动备份到数据目录 `backups/`

> 注意：`volumes/` 是 `data/*.py` 经 `build_volumes.py` 生成的产物。桌面端的改动若要永久固化，需同步回 `knowledge-map/data/` 对应源文件，再重新生成；这一约束在 app 的「使用说明」里也有提示。

也可直接运行源码：`python3 desktop/src/app.py`。

## 常见问题（FAQ）

**需要 API key 或联网吗？**
用提示词生成与本地模板引擎不需要，完全离线可用。用「大模型 API 生成」需要你自己的 Key 并联网；Key 只保存在本机配置文件（权限 600），不会上传到任何服务器，也不会写进题库或导出文件。

**数据和教材版本从哪来？**
以 2022 版义务教育国家课程标准（幼儿园为《3-6 岁儿童学习与发展指南》）为骨架独立梳理，每条知识点标注权威来源；与课标全文逐条机器比对 + 156 条高风险事实点联网复核，结果见 [CROSS_VALIDATION.md](knowledge-map/CROSS_VALIDATION.md)。

**Windows / Linux 能用吗？**
数据与生成管道（Python 3.9+）跨平台；桌面界面基于 Tk，Windows / Linux 理论可运行，目前只在 macOS 上做过完整验证。

**测试连接报 `CERTIFICATE_VERIFY_FAILED` / `unable to get local issuer certificate`？**
不是网络问题，是本机 Python 的根证书库为空（用 python.org 安装包后没跑过证书脚本）。v1.4.1 起会自动改用 macOS 系统证书库，通常无需处理；若仍失败，执行 `open "/Applications/Python 3.11/Install Certificates.command"`，或把公司代理的根证书装进「钥匙串访问」并设为「始终信任」。

**点了「继续」后很久没有任何输出，像卡住了？**

v1.4.3 起不会再出现这种「无声」状态：等待模型响应时右下角显示「已等待 N 秒（单次超时 M 秒）」，限流与超时重试也会在日志里写明「第几次、几秒后重试」。

如果一直是「已等待」而没有结果，通常是输出上限设得太大（例如 40000+）而超时太短。软件会按「输出上限」和「每批题数」自动放宽本次运行的超时（最多 600 秒）并在日志里说明；也可以直接把「等待上限(秒)」改成 240–300 再保存，或把输出上限降到 8192 以内。

**「每次题数」填了 100，为什么日志里还是按 10 题请求？**
v1.8.0 及更早版本把「每次题数」的可填范围限制在 1–10，而且超出范围时是**悄悄改成 10**——界面上还显示 100，看起来像设置没生效。v1.8.1 起范围放宽到 1–100，超出会直接提示「可填 1 ~ 100」，不再静默改值；点「开始生成」或「继续」时按输入框里的当前值生效，不需要先点「保存配置」。一批题数越大，单次写得越长，软件会自动把等待上限放宽（最多 600 秒），被长度上限截断时还会自动折半重试。

**可以自己增删知识点吗？**
可以。桌面端「知识点管理」支持新增 / 编辑 / 删除，带自动备份、撤销与一键恢复出厂配置；要永久固化请改 `knowledge-map/data/*.py` 后运行 `build_volumes.py`。

**可以商用吗？**
MIT 协议，可自由用于商业产品，保留版权声明即可。知识点内容参考国家课标与公开教材，使用前请核对所在地区实际教材版本。
